¿Cómo sé a cuál estoy conectado?

Mira la URL de Supabase: si contiene ltlrujmqenhktiilsnis es dev; si contiene qchpdrolulcgmiliysvr es prod. En tu ordenador, npm run check:env te lo dice. En el panel de Supabase, el nombre del proyecto termina en -dev o en -prod.

Cómo viaja un cambio hasta la web

1 · rama de tareaSe trabaja en una ramaSe reserva la tarea en main y se crea claude/… o codex/….
2 · pull requestLa CI lo pruebaCon el Supabase efímero. Si algo falla, no se fusiona.
3 · mainQueda integradoYa está en el código, pero la web pública todavía no lo tiene.
4 · orden del propietarioSe pasa a releaseSolo con una PR de main a release que aprueba el propietario.
5 · producciónVercel despliegaContra Supabase prod. Antes hay que aplicar allí las migraciones nuevas.

El esquema de la base de datos va por detrás

Cada cambio de tablas o permisos es un fichero de migración. Que el fichero exista en una rama no significa que esté aplicado en una base de datos.

Qué significa en la práctica

Lo que depende de las 8 migraciones nuevas (iconos y privacidad del historial, biografía, bloqueos, búsqueda, comentarios y denuncias) no funciona contra dev hasta que se apliquen. La CI sí lo prueba porque monta su base desde cero. Aplicarlas en dev es la tarea OPS-003, que está bloqueada esperando permiso para hacer antes una copia de seguridad de los datos de dev.
